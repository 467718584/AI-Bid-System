## 1. 代码规范

### 1.1 Java开发规范

**命名规范：**

| 类型 | 规范 | 示例 |
|------|------|------|
| 类名 | UpperCamelCase | `BidProjectService` |
| 方法名 | lowerCamelCase | `getProjectById` |
| 常量 | UPPER_SNAKE_CASE | `MAX_PAGE_SIZE` |
| 变量 | lowerCamelCase | `projectName` |
| 包名 | 全小写 | `com.aidbid.service` |
| 枚举 | UpperCamelCase | `ProjectStatus` |
| 枚举值 | UPPER_SNAKE_CASE | `PROJECT_STATUS_DRAFT` |

**类组织顺序：**

```java
public class XxxService {
    
    // 1. 常量定义
    private static final Logger LOG = LoggerFactory.getLogger(XxxService.class);
    
    // 2. 依赖注入
    @Autowired
    private XxxRepository xxxRepository;
    
    // 3. 公共方法（public）
    public Result<?> doSomething() {
        // validate
        // business logic
        // return
    }
    
    // 4. 私有方法（private）
    private void internalMethod() {
    
    }
}
```

**方法长度：** 单个方法不超过100行，推荐30-50行

### 1.2 Python开发规范

**命名规范：**

| 类型 | 规范 | 示例 |
|------|------|------|
| 类名 | UpperCamelCase | `LLMGateway` |
| 函数名 | snake_case | `get_embedding` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 变量 | snake_case | `document_content` |
| 模块名 | 全小写下划线 | `llm_gateway` |

**代码组织：**

```python
from typing import List, Optional
from langchain import LLMChain

class LLMGateway:
    """LLM统一网关"""
    
    def __init__(self):
        self.providers: Dict[str, LLMProvider] = {}
    
    def chat(self, messages: List[dict], model: str = "minimax") -> str:
        """对话接口"""
        if model not in self.providers:
            raise ValueError(f"Model {model} not found")
        return self.providers[model].chat(messages)
```

**PEP 8标准：**
- 缩进：4个空格
- 行长度：≤120字符
- 导入顺序：标准库 → 第三方库 → 本地库

## 2. Git管理规范

### 2.1 分支命名

| 分支类型 | 命名规范 | 示例 |
|----------|----------|------|
| 主分支 | main | main |
| 开发分支 | develop | develop |
| 功能分支 | feature/{ticket}-{描述} | feature/001-user-login |
| 修复分支 | fix/{ticket}-{描述} | fix/002-login-bug |
| 发布分支 | release/{version} | release/v1.0.0 |

### 2.2 Commit规范

**格式：**

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type类型：**

| Type | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug修复 |
| docs | 文档更新 |
| style | 格式调整 |
| refactor | 重构 |
| test | 测试相关 |
| chore | 构建/工具 |

**示例：**

```
feat(user): 添加用户登录功能

- 实现用户名密码登录
- 添加Token刷新机制
- 添加登录错误重试

Closes #001
```

### 2.3 Merge Request规范

| 项目 | 要求 |
|------|------|

## 3. API设计规范

### 3.1 RESTful规范

| 方法 | 路径 | 说明 | 示例 |
|------|------|------|------|
| GET | /resources | 查询列表 | GET /api/users |
| GET | /resources/{id} | 查询详情 | GET /api/users/123 |
| POST | /resources | 创建资源 | POST /api/users |
| PUT | /resources/{id} | 更新资源 | PUT /api/users/123 |
| DELETE | /resources/{id} | 删除资源 | DELETE /api/users/123 |
| POST | /resources/{id}/action | 执行动作 | POST /api/users/123/reset-password |

### 3.2 命名规范

- 使用小写字母
- 使用名词复数形式
- 使用连字符分隔
- 避免动词（用方法表达）

**推荐：**
- `/api/user-profiles`
- `/api/project-documents`

**不推荐：**
- `/api/getUser`
- `/api/userManagement`

## 4. 数据库规范

### 4.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 数据库 | 小写下划线 | `ai_bid` |
| 表名 | 小写下划线单数 | `sys_user` |
| 字段名 | 小写下划线 | `created_at` |
| 索引名 | idx_{表名}_{字段} | `idx_sys_user_status` |
| 外键名 | fk_{表名}_{关联表} | `fk_user_role_user` |

### 4.2 SQL编写规范

```sql
-- 正确：使用大写关键字，字段换行
SELECT 
    id,
    username,
    created_at
FROM sys_user
WHERE status = 1
ORDER BY created_at DESC;

-- 推荐：使用表别名
SELECT 
    u.username,
    r.role_name
FROM sys_user u
JOIN sys_user_role ur ON u.id = ur.user_id
JOIN sys_role r ON ur.role_id = r.id;
```

## 7. 安全规范

### 7.1 认证与授权

| 规范 | 说明 |
|------|------|
| 密码加密 | BCrypt，强度≥12 |
| Token有效期 | Access Token: 2小时，Refresh Token: 7天 |
| 权限校验 | 所有接口必须校验权限 |
| 敏感数据 | 加密存储，传输用HTTPS |

### 7.2 SQL注入防护

```java
// 推荐：使用参数化查询
@Query("SELECT u FROM User u WHERE u.username = :username")
User findByUsername(@Param("username") String username);

// 禁止：字符串拼接
// "SELECT * FROM user WHERE name = '" + name + "'"
```

### 7.3 XSS防护

```java
// 使用Spring Security的HtmlUtils
String escaped = HtmlUtils.htmlEscape(userInput);

// 前端使用DOMPurify
import DOMPurify from 'dompurify'
const clean = DOMPurify.sanitize(dirty)
```

## 8. 日志规范

### 8.1 日志级别使用

| 级别 | 使用场景 |
|------|----------|
| ERROR | 异常错误，需要立即处理 |
| WARN | 警告，可能存在问题 |
| INFO | 重要业务节点、接口调用 |
| DEBUG | 开发调试信息 |

### 8.2 日志格式

```json
{
  "timestamp": "2026-05-25 10:00:00.000",
  "level": "INFO",
  "logger": "com.aidbid.service.UserService",
  "thread": "http-nio-8080-exec-1",
  "traceId": "uuid",
  "message": "User login success",
  "context": {
    "userId": "uuid",
    "username": "admin",
    "ip": "192.168.1.1"
  }
}
```

### 8.3 日志输出

```java
// 推荐：使用结构化日志
LOG.info("User login success", 
    kv("userId", user.getId()),
    kv("username", username),
    kv("ip", ip));

// 禁止：字符串拼接
// LOG.info("User " + username + " login success");
```
