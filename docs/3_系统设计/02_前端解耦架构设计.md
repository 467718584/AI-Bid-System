# 前端解耦架构设计

## 1. 背景与问题

### 1.1 当前问题
- 前端样式与后端强耦合
- 样式更新需要大批量修改项目
- 前后端职责边界不清晰
- 样式复用性差，维护成本高

### 1.2 解决方案
采用**前后端完全解耦**架构，前端作为独立SPA应用，仅通过API与后端通信。

## 3. 技术栈选型

### 3.1 核心技术

| 技术 | 版本 | 用途 |
|------|------|------|
| Vue | 3.4+ | 渐进式JavaScript框架 |
| Vite | 5.x | 下一代前端构建工具 |
| Element Plus | 2.x | Vue3 UI组件库 |
| Pinia | 2.x | Vue状态管理 |
| Vue Router | 4.x | Vue路由管理 |
| Axios | 1.x | HTTP请求库 |

### 3.2 技术优势

1. **Vite**: 极速开发启动，热模块替换(HMR)
2. **Element Plus**: 成熟稳定的UI组件库，符合企业级应用需求
3. **Pinia**: Vue3官方推荐的状态管理，比Vuex更轻量
4. **组合式API**: 更好的逻辑复用和TypeScript支持

## 4. 样式常量系统（解耦核心）

### 4.1 设计原则

```
样式常量系统架构
├── theme.css      ← 主题配置（颜色、字体、间距）
├── variables.css  ← 全局CSS变量（设计令牌）
└── mixins.css     ← 样式混入（响应式、动画）
```

## 5. API层设计

### 5.1 Axios封装

```javascript
// src/api/index.js
import axios from 'axios'
import { ElMessage } from 'element-plus'

const api = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 30000
})

// 请求拦截器
api.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器
api.interceptors.response.use(
  response => response.data,
  error => {
    ElMessage.error(error.response?.data?.message || '请求失败')
    return Promise.reject(error)
  }
)

export default api
```

### 5.2 模块化API封装

```javascript
// src/api/bid.js
import api from './index'

export const generateOutline = (params) => api.post('/ai/bid/outline', params)
export const generateContent = (params) => api.post('/ai/bid/content', params)
export const getDocument = (id) => api.get(`/document/${id}`)
```

## 6. 状态管理设计

### 6.1 Pinia Store结构

```javascript
// src/stores/bid.js
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useBidStore = defineStore('bid', () => {
  const currentDocument = ref(null)
  const outline = ref([])

  const setOutline = (data) => { outline.value = data }
  const setDocument = (doc) => { currentDocument.value = doc }

  return { currentDocument, outline, setOutline, setDocument }
})
```

## 10. 解耦优势

1. **样式独立**: 通过CSS变量系统，样式更新不影响业务逻辑
2. **前后端分离**: 前端独立部署，不依赖后端技术栈
3. **组件复用**: 公共组件可在多个项目间复用
4. **并行开发**: 前后端可同时开发，互不影响
5. **技术选型灵活**: 前端可独立选择技术栈升级
6. **团队协作**: 明确职责边界，减少冲突
