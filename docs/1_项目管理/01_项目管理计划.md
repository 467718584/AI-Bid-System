## 1. 项目概述

### 1.1 项目背景

当前，以人工智能为核心的新一轮科技革命正驱动各行各业进行深刻变革。2026年2月，国家发展改革委等八部委联合印发《关于加快招标投标领域人工智能推广应用的实施意见》（发改法规〔2026〕195号），作为推进招标投标改革的重要举措和响应国家"人工智能+"行动的重要专项部署，明确技术应用方向、重点应用场景与阶段发展目标，对推动招标投标行业数智化转型、规范市场秩序、提升治理效能具有里程碑意义。

在强力的政策驱动下，我国招投标市场正加速向规范化、精细化、智能化方向发展。招标文件的技术标准日益严苛，评审条款愈加复杂，对投标人的综合能力、响应精度和文件质量提出了前所未有的挑战。因此，构建一套集智能编标、知识沉淀于一体的投标协同管理系统，不仅是顺应国家政策导向、拥抱"人工智能+"浪潮的战略选择，更是企业应对市场激烈竞争、摆脱自身发展困境、实现降本增效和高质量发展的内生需求。

### 1.2 现状与痛点

当前企业投标工作围绕核心业务功能，在投标管理过程中，普遍面临从传统、粗放模式向精细化、智能化转型的阵痛：

| 痛点 | 描述 |
|------|------|
| 管理视角缺失 | 缺乏统一的投标项目管理平台，项目信息分散，管理者难以实时了解公司整体投标态势 |
| 编制效率瓶颈 | 标书编制重度依赖个人经验与手动操作，从海量资料中查找、整合、排版耗时耗力 |
| 合规风险凸显 | 传统人工检查方式耗时费力，且难以避免因疲劳或疏忽导致的错漏 |
| 知识资产散落 | 资质、业绩、方案等核心知识资产分散于各部门或个人手中，未能形成统一知识库 |

### 1.3 项目目标

本项目以"数字化协同、智能化赋能、高质量投标"为核心导向，构建覆盖投标全流程的协同管理系统。通过整合项目管理、AI编标、标书检查优化、知识资产沉淀等核心功能，最终达成：

| 目标 | 量化指标 |
|------|----------|
| 运营提效 | 标书编制平均周期缩短 **30%** 以上 |
| 质量管控 | 非技术性废标风险降低 **90%** 以上 |
| 知识复用 | 可复用内容比例提升至 **50%** 以上 |
| 智能辅助 | AI编标与优化工具得到普遍应用 |
| 数据决策 | 形成多维度业务分析报表 |

### 1.4 项目范围

```
┌─────────────────────────────────────────────────────────────┐
│                    投标全生命周期                           │
├─────────────────────────────────────────────────────────────┤
│  项目立项 → 招标文件解析 → 技术标编制 → 资信标编制 → 审核 → 投标提交  │
└─────────────────────────────────────────────────────────────┘
```

**核心功能模块：**

| 模块 | 功能描述 |
|------|----------|
| 企业知识资产 | 素材库、企业资料库、电子证照、有效期预警 |
| 智能编标 | 招标文件解析、技术标智能编制、资信标智能编制、标书改写 |
| 系统支撑 | 用户权限、工作流配置、技能编排、知识库RAG、模型管理、API管理 |
| 投标管理 | 项目全流程可视化管控、标书检查优化 |

## 8. 技术选型

### 8.1 技术栈总览

```
┌─────────────────────────────────────────────────────────────┐
│                        客户端层                             │
│                  Vue3 + Element Plus + Pinia                 │
├─────────────────────────────────────────────────────────────┤
│                        应用层                              │
│            Spring Boot 3 + MyBatis-Plus + Redis            │
│               FastAPI + LangChain + ChromaDB                │
├─────────────────────────────────────────────────────────────┤
│                      AI能力层                               │
│        LLM Gateway + RAG Engine + Document Parser           │
│             (通义千问/DeepSeek/Minimax API)                  │
├─────────────────────────────────────────────────────────────┤
│                      数据层                                 │
│     PostgreSQL 16 + pgvector │ Redis 7 │ MinIO            │
├─────────────────────────────────────────────────────────────┤
│                      基础设施                               │
│                   Docker + Ubuntu                           │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 关键技术选型理由

| 技术 | 选型 | 理由 |
|------|------|------|
| 数据库 | PostgreSQL + pgvector | 单一数据库减少维护，支持向量检索 |
| 向量库 | Chroma（开发）/ Milvus（生产） | 开发阶段快速验证，后期可切换 |
| LLM | API调用（开发）+ 私有化（生产） | 灵活切换，支持Qwen |
| 工作流 | Flowable | 开源、成熟、BPMN标准 |
| 文件存储 | MinIO | S3兼容、私有化部署 |
